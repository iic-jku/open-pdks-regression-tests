# PEX bench for the ihp-sg13g2 Open-PDK

Metal-only dummy layouts whose parasitics can be computed by hand from the PDK extraction deck, extracted with Magic and with the kpex engines, compared term by term, and checked against expected values.
It is the test that says whether the parasitic extractors in IIC-OSIC-TOOLS implement the deck, and it caught six defects on the first run (see the [report](report/pex_bench_report.html)).

Everything runs inside the IIC-OSIC-TOOLS container from this directory. `make help` lists the targets.

```sh
make pex-bench                  # Magic modes 1/2/3 on every layout, kpex 2.5D on the comparison cells, tables, check
make pex-bench FASTERCAP=1      # also field-solve the comparison cells (KPEX_AMAX=2 by default, minutes)
make pex-bench-defects          # the six defects on their smallest cases, netlists printed
make magic-pex CELL=cross_m1 EXT_MODE=3 MINDELAY=1      # any single cell, any setting
make klayout-pex CELL=sidewall_m1_s0p8 KPEX_ENGINE=2.5D
make layouts                    # regenerate layout/ from scripts/gen_*.py
make layouts-check              # assert the generators still reproduce layout/ byte for byte
```

The layouts are committed as well as generated. `make layouts-check` guards that pair: the generators write GDS with timestamps disabled, so a regeneration that changes nothing produces byte-identical files, and any real change to a generator shows up as a layout diff that has to be committed deliberately.

## Upstream reports

[report/upstream_issues.md](report/upstream_issues.md) holds copyable drafts for the Magic issue tracker, one per finding, each with its minimal case and numbers, and [report/upstream_issue_combined.md](report/upstream_issue_combined.md) the same content as a single consolidated issue. [report/upstream_issues_kpex.md](report/upstream_issues_kpex.md) holds the kpex ones, including the root cause for the sidewall rows of klayout-pex#197, with [report/upstream_issue_kpex_combined.md](report/upstream_issue_kpex_combined.md) as their consolidated form. It also records the search that was done, so a finding already reported upstream is not opened twice: the double-counted coupling capacitance is [magic#550](https://github.com/RTimothyEdwards/magic/issues/550), which the file supplies a reproduction comment for rather than a new issue.

## What is compared

| Column | How it is produced | What it is |
|---|---|---|
| deck | by hand from `$PDKPATH/libs.tech/magic/ihp-sg13g2-extract.tech`, variant `()` | the arithmetic the PDK specifies |
| Magic | `sak-pex.sh`, i.e. `make magic-pex` | Magic's implementation |
| kpex 2.5D | `kpex --2.5D` | a second implementation, reading the identical coefficients from `klayout_pex_protobuf/ihp-sg13g2_tech.pb.json` |
| FasterCap | `kpex --fastercap` | a boundary-element field solve on the kpex process stack, which matches `sg13g2_for_EM.xs` |

`make klayout-pex` with the default `KPEX_ENGINE=magic` is not a further opinion: kpex then drives Magic, and the coupling capacitors are bit-identical to `magic-pex`.

Where Magic and kpex 2.5D disagree, exactly one of them has a bug, and FasterCap arbitrates. That is how the sidewall factor of two was settled.

All in `layout/`, regenerated by `make layouts` from `scripts/gen_*.py`. Each isolates one term.

| Cells | Term | Geometry |

## Outputs and the check

- `netlist/pex/<cell>_magic_pex_<mode>.spice`, `netlist/pex/kpex/2.5D/<cell>/`, `netlist/pex/kpex/fastercap/<cell>_a<amax>/` are the run outputs (ignored by git).
- `scripts/analyse.py` prints tables A to E (deck against Magic), `scripts/compare_engines.py` tables F to I (all engines against the field solve). Both write their values to JSON.
- `scripts/check_results.py` compares that JSON with `expected/results.json`: deck, Magic and kpex 2.5D values to 0.05 %, FasterCap to 5 % (the triangulation is rebuilt every run, so points scatter). FasterCap values are optional in the check.
- `expected/fastercap/` holds the capacitance matrices of the convergence study the report is built on, so `compare_engines.py` shows the converged field-solve column without a multi-hour run. `read_kpex.py <dir>` reads one of them. What is in those files, and which of them the numbers come from, is in [Where the FasterCap numbers come from](#where-the-fastercap-numbers-come-from) below.
- `expected/RESULTS.txt` is the full table set as it stood when the expected values were written.

`make pex-bench-expected` overwrites `expected/results.json` with a fresh run. Do that after a deliberate change (a new tool version that fixes a defect), never to make a failing check pass.

## Where the FasterCap numbers come from

Two knobs, because there are two independent discretisations:

- `--delaunay_amax` is the **KLayout-side** triangulation: the largest triangle, in um^2, that KLayout may hand to FasterCap as a panel. kpex's default of 50 is far too coarse for sub-micron gaps; the bench uses 2 and the convergence study goes to 0.1.
- `--tolerance` is **FasterCap's own** stopping criterion. FasterCap runs in auto mode (`-a<tolerance>`): it solves the panels, prints a capacitance matrix, reports "Automatically increasing the refinement parameters", solves again, and repeats until two successive matrices agree within the tolerance. So the tolerance moves the answer as much as the triangulation does - at `amax 0.5` the sidewall coupling shifts 2 % across tolerance 0.05, 0.01 and 0.005.

The chain from geometry to the number in table F to I:

1. KLayout triangulates and kpex writes a FasterCap `.lst` file.
2. FasterCap iterates as above and writes everything to `<cell>_FasterCap_Output.txt`. Its early iterations are routinely unphysical and it says so: iteration 0 of a 0.2 um sidewall run at `amax 2` produced a positive off-diagonal element, which a Maxwell capacitance matrix cannot have, and FasterCap printed `Warning: capacitance matrix has a non-negative off-diagonal element` and `is not diagonally dominant`. From iteration 1 on it is well formed. **These warnings live only in that log, which `prune.sh` discards, so nothing downstream can see them.** Read the log before trusting a new setting.
3. kpex takes the **last** matrix in the log, divides every entry by 1e6 (the `.lst` geometry is in um), and writes it verbatim as `<cell>_FasterCap_Result_Matrix_Raw.csv`.
4. kpex replaces each off-diagonal pair by its mean, `(C_ij + C_ji) / 2`, leaves the diagonal alone, and writes `<cell>_FasterCap_Result_Matrix_Avg.csv`.

Neither CSV is FasterCap's own format; both are kpex's, written by `run_fastercap_extraction` in `kpex_cli.py`.

**Raw and Avg differ only in symmetry, and each has one job.** The capacitance matrix must be symmetric - `C_ij = C_ji` follows from reciprocity - so every asymmetry in Raw is numerical error from the panelisation and the iterative solve. That makes it a free error estimate that needs no reference value. `read_kpex.py` therefore takes the **values** from Avg and the **error bar** from Raw:

```
coupling  C_ij = -M[i][j]                        from Avg
residual  M[i][i] - sum over j != i of -M[i][j]  from Avg
asymmetry sum |Raw_ij - Raw_ji| / sum max(...)   from Raw, weighted by magnitude,
                                                 entries below 0.1 fF ignored
```

Both files are needed, which is why `expected/fastercap/` keeps both.

A worked example, `sidewall_m1_s0p2` at `amax 0.1`, `tolerance 0.01`. Raw:

```
             g1_VSUBS      g2_$2         g3_$3
g1_VSUBS   1.21158e-14  -3.23667e-15  -3.22906e-15
g2_$2     -3.23082e-15   9.6119e-15   -6.21943e-15
g3_$2     -3.24395e-15  -6.2196e-15    9.62465e-15
```

`C(1,2)` and `C(2,1)` differ by 0.18 %, and the weighted asymmetry over the whole matrix is 0.16 %. Avg replaces both by -3.233745e-15. The wire-to-wire coupling reported in table H is `-(-6.219515e-15) = 6.2195 fF`, and net 2's far-field residual is `9.6119 - (3.2337 + 6.2195) = 0.159 fF`.

## Provenance of the committed matrices

`expected/fastercap/<cell>_a<amax>_b<delaunay_b>_t<tolerance>/` encodes its own settings in the directory name; `<cell>_a<amax>` without the suffix is an older run at the defaults. `fc_finest(cell)` in `compare_engines.py` walks `FINE` from fine to coarse and takes the first setting that has a result, so the column is per cell the finest solve that exists - `amax 0.1` for the sidewall cells, `amax 2` for the 50 x 50 um plates, which do not converge finer in reasonable time.

`scripts/make_fastercap_expected.sh` in the repository root produces a set for any PDK and writes a `PROVENANCE.md` next to the matrices with the tool versions, the date, the sweep and the cells that did not converge. Use it rather than copying by hand, and see its `--calibrate` mode for choosing the settings: neither "two successive `amax` agree" nor "the asymmetry is small" is a safe stopping rule on its own. The sequence is not monotone, and at `amax 50` this bench's tightest gap has the *best* asymmetry of all the coarse runs while sitting 9.6 % below the converged value.

Aim for a reference an order tighter than the 5 % that `check_results.py` allows the FasterCap column to drift. A reference that is itself only good to 5 % makes the check unable to tell a real change from its own noise.

## Running kpex FasterCap correctly

`--mesh` does nothing: kpex calls FasterCap in auto mode (`-a<tolerance>`), and FasterCap prints "Auto option overrides all other Manual settings", so `-m` and `-d` are ignored. The knobs that matter are `--delaunay_amax` (the KLayout-side triangulation, default 50 um^2, worth 11 % on a 0.2 um gap) and `--tolerance`.

Judge convergence from the raw-matrix asymmetry, which `read_kpex.py` reports weighted by magnitude and thresholded at 0.1 fF. Below about 0.2 % the answer has settled. `capsub_tm2` at 18 % is not converged and must not be quoted, which is why the report greys those rows out. The 50 x 50 um plates do not converge at `amax 0.5` in reasonable time (an hour of CPU, 6.6 GB), so the substrate rows are quoted at `amax 2` with the trend stated.

kpex reports the far-field residual (`Cext_i_i`, flux leaving the simulation box) tied to VSUBS. It is a boundary artifact, not substrate capacitance, and belongs in its own column. And on a layout with devices the totals are not comparable to Magic at all: Magic excludes the device region because the compact models cover it, FasterCap treats gate and diffusion as plain conductors. Only device-less structures give an apples-to-apples capacitance comparison, which is why the bench is metal-only.

## The investigation scripts

The `scripts/try_*.sh` and `scripts/kpex_*.sh` files are the sweeps that found and isolated the defects. They are kept as the record of how each conclusion was reached and are run by `make pex-bench-defects`.

| Script | What it answers |
|---|---|
| `try_res.sh`, `try_res2.sh`, `try_res3.sh` | which extresist setting lets a resistor through, on 2-port, 3-port and branched nets |
| `try_tee.sh` | which knob turns a correct star into a 2-resistor chain (`MINDELAY`) |
| `try_dbl.sh` | which setting makes the coupling cap also appear lumped to substrate |
| `try_sw.sh` | whether `sidewall` and `defaultsidewall` give the same answer (they do, both half) |
| `try_ext2spice.sh` | which `ext2spice` option makes magic-pex and klayout-pex disagree (`hierarchy on`) |
| `try_hier.sh` | the standard cell with the 200 um gate wire, hierarchy on and off |
| `try_kpexrecipe.sh` | Magic's full-RC driven by kpex's recipe instead of sak-pex's |
| `kpex_conv.sh`, `kpex_sw.sh`, `kpex_ref.sh`, `kpex_run.sh` | the FasterCap convergence study and the two-triangulation bench |
| `reverify.sh` | every number the report leans on, re-extracted into clean directories with the expected value beside it |
| `prune.sh` | drop FasterCap input meshes and geometries, keep the result matrices |

## Notes for anyone extending this

- Magic measures resistance between the label positions, not the wire ends. A 100 um wire with ports 0.5 um in from each end is 99 squares.
- Keep via cuts inside the landing metal and on legal spacing. Cuts that fall off the metal make it look as though Magic is miscounting parallel vias when it is counting exactly what is there.
- Structures meant not to couple must be more than `sidehalo` (8 um) apart. The bench uses 60 um.
- Text on the pin datatype (`8/2` for Metal1) becomes a port. The pin box is OR'ed into the metal, so keep it inside the drawn shape.
- kpex names the dummy nets `$2`, `$3` because there is no schematic to match against. `compare_engines.py` identifies them by magnitude, which only works because the bench shapes are deliberately very different in size.
- Never `pkill -f` a pattern that appears in your own command line. Use `pkill -x FasterCap`.
